# Context & Memory Management

This document explains how to preserve context and memory when jumping between different AI coding platforms (Claude Code, OpenCode, Antigravity, etc.)

## The Problem

When switching AI platforms mid-project:
- Session context is lost
- Decisions made on one platform aren't visible on another
- Memory of patterns/pitfalls doesn't carry over
- Each platform needs its own configuration

## The Solution: GBrain + Checkpoint Mode

### Option 1: GBrain (Recommended)

GBrain is a persistent knowledge base that syncs across platforms. All learnings, decisions, and insights stay available.

**Setup (one-time):**
```bash
/setup-gbrain
```

Choose:
- **PGLite local** — single machine, zero network, ~30 seconds
- **Supabase cloud** — team sync, persistent across machines

**What gets saved:**
- Design documents from `/office-hours`
- Architecture decisions from `/plan-eng-review`
- Test plans and edge cases
- Debugging insights from `/investigate`
- Design preferences learned by `/design-shotgun`
- Performance baselines
- Security findings

**Usage:**
- Automatic — all skills save learnings
- Manual — `/learn` to review/prune/export
- Sync — works across all platforms automatically

**Example workflow:**

```
Morning (Claude Code):
  /office-hours → Design doc auto-saved to GBrain
  /plan-eng-review → Architecture auto-saved to GBrain

Afternoon (OpenCode):
  Load gstack
  → Sees latest design doc in GBrain
  /qa → References architecture from GBrain
  → Findings saved back to GBrain

Evening (Antigravity):
  /investigate → Reads all prior learnings
  → Debugging insights saved to GBrain
```

### Option 2: Checkpoint Mode (Advanced)

If you prefer local-only context without external services:

```bash
gstack-config set checkpoint_mode continuous
```

This auto-commits `WIP:` prefix commits with structured `[gstack-context]` bodies. Use `/context-restore` to read commits and reconstruct state.

**Tradeoffs:**
- ✅ Local only, no external network
- ✅ Works offline
- ❌ Only visible on same machine
- ❌ Lost if you git reset

### Option 3: Manual Context Files

Create a shared context file in your project repo:

**.claude/context/active-decisions.md**
```markdown
# Active Decisions

## BugProof Docker Export Feature
- Status: In planning phase
- Owner: Claude Code session started at 2026-05-03T14:00Z
- Architecture: Streaming with 50MB chunk limit
- Open questions:
  - [ ] Error handling for incomplete exports?
  - [ ] Retry logic for network failures?

## Discovered Issues
- Pipeline hangs on 50MB+ artifacts (in Antigravity session)
- Root cause: Timeout on pipe stream (timeout=30s, actual=60s needed)
- Fix: Increase timeout or chunk smaller

## Design Decisions
- Use protobuf for export format (vs gzip + tar)
- Reason: Better streaming support, smaller overhead
```

**Usage:**
1. Update manually before switching platforms
2. Each platform reads this file first
3. Include date/time of last update
4. Document open questions

## Cross-Platform Workflow Checklist

### Before switching platforms:

- [ ] Run `/review` on current branch (catch bugs)
- [ ] Run `/ship` if ready (merge to main)
- [ ] Commit any WIP work with `WIP:` prefix if using checkpoint mode
- [ ] Update `.claude/context/active-decisions.md` if not using GBrain
- [ ] Take screenshot of current state (optional, for manual reference)

### When switching to new platform:

```bash
# 1. Load gstack
/setup                    # or ./setup if not already done

# 2. Read context
/learn                    # if using GBrain
# or manually read .claude/context/active-decisions.md

# 3. Restore previous work
/context-restore          # if using checkpoint mode

# 4. Resume where you left off
/qa https://...
# or
/review
```

## Platform-Specific Configuration

Each platform stores its config locally to avoid cross-contamination:

```
~/.claude/              → Claude Code config (gstack, CLAUDE.md)
~/.config/opencode/     → OpenCode config
~/.cursor/              → Cursor config
~/.antigravity/         → Antigravity config
~/.openclaw/            → OpenClaw config
```

However, **shared state** lives in the project:

```
BugProof/
├── .claude/context/          ← Manual context (shared)
├── CLAUDE.md                 ← Shared guidelines
├── CONTRIBUTING.md           ← Shared workflow
├── DESIGN.md                 ← Auto-generated by /office-hours
├── ARCHITECTURE.md           ← Auto-generated by /plan-eng-review
└── .gstack/                  ← Local gstack state per platform
```

## Troubleshooting

### "Context lost when I switched platforms"

**Solution:** Set up GBrain
```bash
/setup-gbrain
```

### "Different platforms have different skill versions"

**Solution:** Each platform auto-updates independently. Run:
```bash
/gstack-upgrade
```

on each platform to sync.

### "My learnings are duplicated"

**Solution:** GBrain deduplicates automatically. Or manually clean up:
```bash
/learn search [keyword]
/learn prune [old-session-id]
```

### "I want to work offline"

**Solution:** Use checkpoint mode instead of GBrain cloud:
```bash
gstack-config set checkpoint_mode continuous
```

Then all context is local commits in your repo.

---

## Best Practices

1. **Always use GBrain if possible** — it's the least painful way to sync context across platforms
2. **Commit frequently** — especially before switching platforms
3. **Update DESIGN.md and ARCHITECTURE.md** — these are your human-readable context
4. **Use `/learn` weekly** — review what the AI learned, prune stale insights
5. **Include session context in commit messages** — helps with manual handoffs
